# Deterministic Synthetic 300 Mb input

`generate_synthetic_300M.py` reconstructs the exact single-record FASTA used
for the accepted Figure 2, Figure 3, and matched-workload ntHash results. The
generated file is external data and must not be committed.

## Historical recovery

The historical `random.c` program was recovered from the author's working
archive during the final input audit. It seeded the host C library with
`srand(time(0))`, mapped
`rand() % 4` as `0=A`, `1=T`, `2=C`, `3=G`, read an interactive length, and
always wrote `AEEE.fasta`. Its seed was recovered as `1781167332`; replaying
that glibc stream matched all 300,000,000 bases of the accepted FASTA.

The historical source is not published unchanged because wall-clock seeding,
interactive input, a fixed output name, and host-libc `rand()` behavior are
not portable. Its FASTA header also names a Bacillus genome even though the
record is synthetic.

## Portable exact reconstruction

The public Python generator implements the glibc TYPE_3 additive recurrence,
Park-Miller initialization, 344-value warm-up, and unsigned 32-bit arithmetic
directly. It therefore does not call the host C library. It uses:

- fixed seed: `1781167332`;
- sequence length: `300000000` bases;
- nucleotide mapping: low two output bits `0=A`, `1=T`, `2=C`, `3=G`;
- binary `\n` newlines and one unwrapped sequence line;
- the legacy header bytes required for the accepted file identity.

The legacy header is retained only for byte-exact reconstruction and must not
be interpreted as biological provenance.

## Generate and verify

From the repository root, choose a new external output path:

```sh
python3 reproducibility/data_generation/synthetic_300M/generate_synthetic_300M.py \
  --output /data/AEEE.fasta
```

The generator streams bounded chunks, uses about a few tens of MiB of memory,
refuses an existing output, prints the generated byte size and SHA-256, and
deletes a formal output if its identity is unexpected. Expected identity:

| Filename | Sequence bases | Size [bytes] | SHA-256 |
|---|---:|---:|---|
| `AEEE.fasta` | 300,000,000 | 300,000,057 | `a7eca29bdfa06ff373048fffa7a90139afc98acfa938a8ec0a98459608045962` |

The observed accepted base counts are A 75,007,422; C 74,998,890;
G 75,002,293; and T 74,991,395. `expected_sha256.tsv` is the machine-readable
identity record.

## Lightweight test

```sh
make synthetic-generator-test
```

The test generates only short prefixes, checks a recovered 256-base historical
prefix, validates binary FASTA formatting and determinism, and verifies
overwrite refusal. CI never generates the 300 MB file. The optional
`--length` argument exists only for these lightweight checks; accepted formal
reconstruction uses the default length.

## Use in formal workflows

Pass the generated path as the `Synthetic_300M` dataset in the Figure 2,
Figure 3, and Table 4 commands. Each workflow README shows the exact command.
Before using an existing file, verify:

```sh
printf '%s  %s\n' \
  a7eca29bdfa06ff373048fffa7a90139afc98acfa938a8ec0a98459608045962 \
  /data/AEEE.fasta | sha256sum --check --strict
```
